# Task Service

Task Service is a REST API for creating and managing tasks. It is built with FastAPI, SQLAlchemy, and PostgreSQL, and includes health checks, centralized error handling, request logging, and Docker support.

## Features

- Create, read, update, replace, and delete tasks
- List all tasks or clear the table
- Health check endpoints for liveness and database readiness
- Pydantic validation for request and response models
- Layered architecture with `api`, `services`, and `repositories`
- Automatic database table creation on startup
- Request logging middleware
- Dockerfile and Docker Compose setup

## Tech Stack

- Python 3.11
- FastAPI
- SQLAlchemy

## Task Model

Each task includes:

- `id`: integer, generated by the database
- `title`: required string, trimmed, 1 to 255 characters
- `info`: optional string
- `created_at`: UTC timestamp set when the task is created
- `execute_at`: optional UTC timestamp

If `execute_at` is omitted when creating a task, the service sets it to one minute after `created_at`.

## Environment Variables

| Variable      | Default                                              | Description                  |
| ------------- | ---------------------------------------------------- | ---------------------------- |
| `APP_NAME`    | `Task Service`                                       | FastAPI application title    |
| `APP_VERSION` | `1.0.0`                                              | API version                  |
| `DB_URL`      | `postgresql://user:password@localhost:5432/tasks_db` | PostgreSQL connection string |

## Running Locally

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Start PostgreSQL

Make sure a PostgreSQL database is running and matches `DB_URL`.

Default local connection:

```text
postgresql://user:password@localhost:5432/tasks_db
```

### 3. Start the API

```bash
uvicorn app.main:app --reload
```

The service will be available at `http://localhost:8000`.

## Running with Docker Compose

```bash
docker compose up --build
```

This starts:

- `db`: PostgreSQL 15 on port `5432`
- `app`: FastAPI service on port `8000`

The Docker Compose app container uses:

```text
postgresql://user:password@db:5432/tasks_db
```

## Running Tests

```bash
python -m unittest discover -s tests -v
```

The test suite uses a temporary SQLite database, so it does not require a running PostgreSQL container.

## API Endpoints

| Method   | Path               | Description                         |
| -------- | ------------------ | ----------------------------------- |
| `GET`    | `/`                | Service status                      |
| `GET`    | `/health/live`     | Liveness check                      |
| `GET`    | `/health/ready`    | Readiness check with database query |
| `GET`    | `/tasks`           | List all tasks                      |
| `GET`    | `/tasks/{task_id}` | Get a task by ID                    |
| `POST`   | `/tasks`           | Create a task                       |
| `PATCH`  | `/tasks/{task_id}` | Partially update a task             |
| `PUT`    | `/tasks/{task_id}` | Replace a task                      |
| `DELETE` | `/tasks/{task_id}` | Delete a task by ID                 |
| `DELETE` | `/tasks`           | Delete all tasks                    |
| `POST`   | `/tasks/reset`     | Truncate the table and reset IDs    |

FastAPI also exposes interactive docs at:

- `http://localhost:8000/docs`
- `http://localhost:8000/redoc`

## Example Request

### Create a task

```http
POST /tasks
Content-Type: application/json

{
  "title": "Prepare deployment checklist",
  "info": "Review database backup and environment variables",
  "execute_at": "2026-03-29T10:30:00Z"
}
```

### Example response

```json
{
  "id": 1,
  "title": "Prepare deployment checklist",
  "info": "Review database backup and environment variables",
  "created_at": "2026-03-28T20:15:00.000000Z",
  "execute_at": "2026-03-29T10:30:00Z"
}
```

## Notes

- Database tables are created automatically during application startup.
- The readiness check runs `SELECT 1` against PostgreSQL.
- Missing task lookups return `404`.
- Unhandled server errors return `500`.
- Each request is logged with method, path, status code, and duration.
